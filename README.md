# Розмальовка

React/Vite-клієнт і Express API запускаються як один Node.js сервіс. Express віддає production-збірку з `dist` і обробляє API-запити за шляхом `/api`.

PDF-редактор автоматично кадрує додані фото по центру до формату A4 2480 × 3508 px. Ручне A4-кадрування, масштаб і наклейки залишаються доступними за бажанням. PDF можна імпортувати сторінками-зображеннями, потім переставляти, видаляти чи замінювати окремі сторінки та експортувати новий PDF. Текст і шари імпортованого PDF не редагуються окремо. Кнопка **«Обкладинка»** додає передню сторінку на початок, а задню — в кінець журналу. У редакторі AI-розмальовок кнопку **«У PDF»** можна використати, щоб передати всі готові активні версії в PDF-редактор без завантаження файлів на комп'ютер.

## Локальний запуск

Створіть `.env` у корені проєкту:

```env
OPENAI_API_KEY=ваш_ключ_OpenAI
PORT=3001
```

Встановіть залежності та запустіть клієнт і API в різних терміналах:

```powershell
npm install
npm run server
npm run dev
```

У режимі розробки Vite проксить `/api` на `http://localhost:3001`.

## AI-дизайнер (чат)

Картка «AI-дизайнер (чат)» у меню — вільний чат з AI: можна додавати фото й приклади макетів, просити аналіз, ідеї та створення зображень. Результат можна завантажити, доробити далі або одразу відправити в PDF-редактор чи редактор календариків і наклейок (відкривається в новій вкладці). Ендпоінт — `POST /api/aichat/message` (`server/aichat.js`). Необов'язкові змінні: `AICHAT_MODEL` (за замовчуванням `gpt-4o-mini`) і `OPENAI_IMAGE_MODEL`.

## Бізнес-чат

У вкладці «Бізнес-чат» можна вручну завантажувати діалоги з Messenger та Instagram, шукати серед завантажених чатів за ім’ям або username, переглядати фото клієнта, відповідати текстом через Meta та передавати вибрані фото в редактор AI-розмальовок без введення імені дитини. Кнопка зовнішнього посилання відкриває вибрану розмову на сайті відповідного сервісу. Сторінки Meta зазвичай не дозволяють вбудовування в iframe через політику безпеки браузера. Для Messenger доступне підвантаження старіших повідомлень і фото; Instagram Graph API повертає лише 20 останніх повідомлень діалогу. Meta також обмежує звичайні відповіді часовим вікном (зазвичай 24 години) та дозволами застосунку.

Додайте згенеровані Page Access Tokens лише у локальний `.env`:

```env
META_MESSENGER_PAGE_ACCESS_TOKEN=...
META_INSTAGRAM_PAGE_ACCESS_TOKEN=...
META_PAGE_ID=ідентифікатор_сторінки
```

Перезапустіть сервер після зміни `.env`. Значення токенів не додавайте у `VITE_*`, коміти, скриншоти або повідомлення. Локальний API доступний лише з цього комп'ютера; у production доступ до Business Chat захищено паролем. Instagram Conversations API може вимагати підтверджений Meta Business, відповідні дозволи та App Review для діалогів людей без ролі в застосунку.

### Railway

Підключіть GitHub-репозиторій і налаштуйте сервіс із кореневою директорією репозиторію:

- Build command: `npm run build`
- Start command: `npm start`
- Healthcheck path: `/api/health`

У Railway → **Variables** додайте ключ OpenAI та змінні Meta:

```env
OPENAI_API_KEY=...
META_MESSENGER_PAGE_ACCESS_TOKEN=...
META_INSTAGRAM_PAGE_ACCESS_TOKEN=...
META_PAGE_ID=...
META_API_PASSWORD=...
META_APP_ORIGIN=https://<домен-сервісу>.up.railway.app
```

Для `META_API_PASSWORD` задайте власний випадковий пароль довжиною щонайменше 16 символів. `META_APP_ORIGIN` має точно збігатися з публічним URL сайту, включно з `https://`, без `/` у кінці. Якщо її не задано, сервер спробує використати Railway-змінну `RAILWAY_PUBLIC_DOMAIN`. `META_GRAPH_API_VERSION` необов'язкова (типово `v27.0`); `PORT` задає Railway автоматично. Після додавання змінних зачекайте на redeploy і відкрийте Business Chat — пароль потрібно вводити повторно кожні 12 годин. Не додавайте пароль чи токени у `VITE_*`, GitHub або чат.

Meta може не повертати фото профілю без окремих прав: для Instagram перевірте `pages_show_list` разом із дозволами Instagram Messaging; для Messenger потрібен доступ до Business Asset User Profile Access і, для клієнтів без ролі в застосунку, схвалення Meta. Якщо доступу немає, чат показує ініціали замість фото. У назви переданих в AI файлів автоматично додається ім’я або username клієнта.

### Розширення Chrome для фото з чатів

1. У Chrome відкрийте `chrome://extensions`, увімкніть **Режим розробника** і натисніть **Завантажити розпаковане розширення**. Виберіть папку `browser-extension/meta-photos`.
2. Відкрийте потрібний діалог на Instagram, Facebook або Messenger. Натисніть значок розширення → **Показати кнопки в чаті**.
3. Натискайте **+** поверх потрібних фото у повідомленнях; прокручуйте історію, щоб вибрати інші. Кнопка **Фото** на панелі показує вибрані мініатюри: їх можна збільшити, вибрати або прибрати. **Знайти фото** шукає завантажені фото; **Сканувати історію** прокручує діалог для завантаження старіших і новіших повідомлень, її можна зупинити. **Вибрати знайдені** додає результати до вибору. За бажанням введіть ім'я клієнта.
4. Натисніть **В AI** на панелі або **Передати в AI** у вікні розширення. Фото передаються в нову вкладку Railway без завантаження на комп'ютер; після імпорту вони готові до роботи в редакторі. Під час передачі з вікна розширення не закривайте його, доки не відкриється редактор.

Позначки з'являються лише на знайдених фото в області повідомлень; розширення намагається відфільтрувати аватари, але Meta може змінювати розмітку — перевіряйте вибір. Автоматично відрізнити фото клієнта від ваших воно не може. Пошук обробляє зображення лише локально, не читає та не надсилає текст переписки. Навіть під час сканування Meta може не завантажити всі старі фото; сканування обмежене 500 фото або 250 кроками у кожному напрямку. Якість фото залежить від зображення, яке показала Meta. Вибір тримається у вкладці та очищається після перезавантаження або зміни діалогу. Підтримуються JPEG, PNG і WebP; за раз можна передати до 20 фото сумарно до 20 МБ. Якщо Meta не дозволяє отримати фото або змінить структуру сайту, імпорт може не спрацювати. Розширення передає фото тільки на вказану Railway-адресу й не потребує Meta-токена.

## Telegram-бот для фото

1. У Telegram відкрийте офіційний **@BotFather**, введіть `/newbot` і створіть бота. Токен зберігайте лише у Railway Variables, не надсилайте в чат і не додавайте в GitHub.
2. У Railway додайте `TELEGRAM_BOT_TOKEN` і `TELEGRAM_ALLOWED_USER_IDS`. Для початкового налаштування ID можна тимчасово вказати `0`. За потреби задайте `TELEGRAM_APP_ORIGIN` як HTTPS-адресу сайту без `/` у кінці; якщо не задано, використовується `RAILWAY_PUBLIC_DOMAIN`.
3. Після redeploy відкрийте бота і натисніть `/start`. Кожен працівник отримає свій цифровий Telegram ID; попросіть його передати ID адміністратору. Додайте дозволені ID у `TELEGRAM_ALLOWED_USER_IDS` через кому, наприклад `123456,789012`, і дочекайтеся redeploy.
4. У приватному чаті натисніть **Надіслати фото в AI розмальовки**, надішліть або перешліть фото, потім натисніть **Передати в AI розмальовки**. Відкрийте отримане посилання: редактор завантажить фото. Кнопка **Очистити фото** очищає поточний набір.

Доступ до бота мають тільки вказані ID, групи не підтримуються. Кожен користувач має окремий набір: до 20 фото JPEG, PNG чи WebP сумарно до 20 МБ. Telegram може стискати зображення, надіслані як фото; для оригінальної якості надсилайте зображення як файл. Посилання одноразове, діє 30 хвилин і дає доступ до фото будь-кому, хто його має: не пересилайте його. При помилці завантаження відкрийте посилання ще раз; після успішного відкриття воно більше не діє. Набори та посилання тимчасово зберігаються в пам'яті сервера і зникають після перезапуску або redeploy — тоді фото потрібно надіслати знову. Для long polling запускайте лише одну репліку Railway-сервісу; той самий токен не можна одночасно використовувати іншим ботом чи webhook.

Попередній конвеєр «фото → обкладинка/календарик/наклейки» збережено в `src/legacy` і `server/legacy` (у меню й на сервері вимкнений).

## AI-розмальовки: фактичні витрати

Редактор автоматично бере кількість зображень та фактичні витрати з OpenAI Usage/Costs API, показує підсумок за сьогодні і середню вартість на зображення. Для цього потрібен окремий Admin API key у `OPENAI_ADMIN_KEY`; звичайного `OPENAI_API_KEY` недостатньо. Ключ використовується лише сервером і ніколи не передається в браузер. Необов'язковий `OPENAI_PROJECT_ID` обмежує звіт одним проєктом.

Якщо `USD_TO_UAH` залишити порожнім, сервер бере курс USD/UAH з НБУ; його можна задати вручну у `.env`, якщо потрібен фіксований курс. OpenAI звітує про витрати із затримкою, а Costs API показує агреговані дані за організацією/проєктом, тому середнє на сторінку є орієнтиром, а не точним чеком конкретної генерації чи доступним балансом.

Usage API для Images API повертає число зображень, але не токени. Якщо відповідь конкретної моделі містить `usage`, редактор збереже ці токени для версії; для `gpt-image-2` OpenAI може не повертати розкладку токенів. Щоб не показувати вигадані числа, у такому разі відображаються фактичні витрати й кількість зображень із агрегованого звіту. Додаткові параметри генерації вибираються галочками; кожна перегенерація є новою платною генерацією.

Змінні прикладу розміщені у [.env.example](./.env.example). Модель задається через `OPENAI_IMAGE_MODEL` (за замовчуванням `gpt-image-2`).

Railway автоматично надає змінну `PORT`; не задавайте її вручну. Сервіс обслуговує клієнт і API на одному домені. Перевірте API за адресою `https://<домен-сервісу>/api/health`.

Не завантажуйте `.env` у GitHub і не додавайте ключ OpenAI до клієнтських змінних `VITE_*`.
