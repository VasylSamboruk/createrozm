# Розмальовка

React/Vite-клієнт і Express API запускаються як один Node.js сервіс. Express віддає production-збірку з `dist` і обробляє API-запити за шляхом `/api`.

PDF-редактор автоматично кадрує додані фото по центру до формату A4 2480 × 3508 px. Ручне A4-кадрування, масштаб і наклейки залишаються доступними за бажанням. PDF можна імпортувати сторінками-зображеннями, потім переставляти, видаляти чи замінювати окремі сторінки та експортувати новий PDF. Текст і шари імпортованого PDF не редагуються окремо. Кнопка **«Обкладинка»** додає передню сторінку на початок, а задню — в кінець журналу. У редакторі AI-розмальовок кнопку **«У PDF»** можна використати, щоб передати всі готові активні версії в PDF-редактор без завантаження файлів на комп'ютер.

## Локальний запуск

Створіть `.env` у корені проєкту:

```env
OPENAI_API_KEY=ваш_ключ_OpenAI
PORT=3001
```

Встановіть залежності та запустіть клієнт і API в різних терміналах:

```sh
npm install
npm run server
npm run dev
```

У режимі розробки Vite проксить `/api` на `http://localhost:3001`.

## AI-дизайнер (чат)

Картка «AI-дизайнер (чат)» у меню — вільний чат з AI: можна додавати фото й приклади макетів, просити аналіз, ідеї та створення зображень. Результат можна завантажити, доробити далі або одразу відправити в PDF-редактор чи редактор календариків і наклейок (відкривається в новій вкладці). Ендпоінт — `POST /api/aichat/message` (`server/aichat.js`). Необов'язкові змінні: `AICHAT_MODEL` (за замовчуванням `gpt-4o-mini`) і `OPENAI_IMAGE_MODEL`.

Попередній конвеєр «фото → обкладинка/календарик/наклейки» збережено в `src/legacy` і `server/legacy` (у меню й на сервері вимкнений).

## AI-розмальовки: фактичні витрати

Редактор автоматично бере кількість зображень та фактичні витрати з OpenAI Usage/Costs API, показує підсумок за сьогодні і середню вартість на зображення. Для цього потрібен окремий Admin API key у `OPENAI_ADMIN_KEY`; звичайного `OPENAI_API_KEY` недостатньо. Ключ використовується лише сервером і ніколи не передається в браузер. Необов'язковий `OPENAI_PROJECT_ID` обмежує звіт одним проєктом.

Якщо `USD_TO_UAH` залишити порожнім, сервер бере курс USD/UAH з НБУ; його можна задати вручну у `.env`, якщо потрібен фіксований курс. OpenAI звітує про витрати із затримкою, а Costs API показує агреговані дані за організацією/проєктом, тому середнє на сторінку є орієнтиром, а не точним чеком конкретної генерації чи доступним балансом.

Usage API для Images API повертає число зображень, але не токени. Якщо відповідь конкретної моделі містить `usage`, редактор збереже ці токени для версії; для `gpt-image-2` OpenAI може не повертати розкладку токенів. Щоб не показувати вигадані числа, у такому разі відображаються фактичні витрати й кількість зображень із агрегованого звіту. Додаткові параметри генерації вибираються галочками; кожна перегенерація є новою платною генерацією.

Змінні прикладу розміщені у [.env.example](./.env.example). Модель задається через `OPENAI_IMAGE_MODEL` (за замовчуванням `gpt-image-2`).

## Розгортання одного сервісу на Railway

Підключіть GitHub-репозиторій і налаштуйте сервіс із кореневою директорією репозиторію:

- Build command: `npm run build`
- Start command: `npm start`
- Variable: `OPENAI_API_KEY` зі значенням вашого ключа
- Healthcheck path: `/api/health`

Railway автоматично надає змінну `PORT`; не задавайте її вручну в Railway. Сервіс обслуговує клієнт і API на одному домені. Перевірте API за адресою `https://<домен-сервісу>/api/health`.

Не завантажуйте `.env` у GitHub і не додавайте ключ OpenAI до клієнтських змінних `VITE_*`.
